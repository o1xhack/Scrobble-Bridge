# Scrobble Bridge 1.0 implementation status

This document describes the public MVP source tree and distinguishes tested product behavior from separately authorized publishing actions.

## Implemented product

| Area                        | 1.0 behavior                                                                                                                                                                  |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Listening history           | YouTube Music cloud-history window, first-run baseline, dense ordered alignment, repeated-play handling, safe history-gap detection and estimated timestamps.                 |
| Last.fm delivery            | Individual browser authorization, signed API requests, SQLite outbox, deterministic fingerprints, recent-track reconciliation, retry/reject states and interruption recovery. |
| Official desktop onboarding | Maintainer-provided Last.fm application credentials can be injected at build time; listeners authorize their own account without entering an API key or shared secret.        |
| Self-hosting                | Source builds without bundled credentials and NAS installations retain a bring-your-own Last.fm application flow.                                                             |

| NAS                         | Non-root amd64 / arm64 Docker image, persistent SQLite, encrypted credential vault, protected Web UI, health checks and replay-resistant paired devices.                      |
| Distribution preparation    | Public GitHub source, Rust/frontend CI, maintainer-configurable artifact workflow, signed-build hooks and validated production Chrome extension ID support.                   |

## Tested failure and recovery behavior

- Missing or half-configured Last.fm application credentials fail closed; existing user-provided credentials are never overwritten.
- Cookie expiration, HTTP 401/403, invalid Last.fm authorization, temporary upstream outages, HTTP 429/503 and unrecognized YouTube history are classified separately.
- Last.fm reauthorization immediately releases authentication-blocked outbox entries while preserving unrelated retry backoff.
- A process interrupted during submission checks Last.fm recent tracks after restart before submitting again.
- A history gap cannot replace the previous safe snapshot; future scheduler ticks remain active.
- A rejected individual song does not permanently stop later YouTube Music synchronization.
- Incomplete setup does not leave the desktop status stuck at `syncing`.
- Pause survives restart; long sleep gaps trigger catch-up even when macOS pauses its monotonic clock, without replaying every missed timer tick.
- Browser multi-account parsing rejects missing, malformed, delegated and out-of-range account contexts safely.
- Cookie, API secrets, account sessions and personal account names are excluded from public fixtures and documentation.

## Previously verified real macOS path

The existing signed macOS installation has already completed real Chrome Native Messaging credential delivery, YouTube Music account discovery, Last.fm authorization, accepted scrobbles and repeated no-change synchronization without duplicate submission. Public documentation intentionally omits the connected accounts and listening history.

## Separate release gates

Public source-code availability is not equivalent to a signed/notarized binary release, a Chrome Web Store listing, a published Docker image or a GitHub Release.

- GitHub Actions secrets `SCROBBLE_LASTFM_API_KEY` and `SCROBBLE_LASTFM_SHARED_SECRET` are configured as a pair for the default official artifact workflow; their values are never stored in the public repository.
- Once Chrome Web Store assigns the production extension ID, set `SCROBBLE_PRODUCTION_EXTENSION_ID` as a GitHub repository variable and rebuild the desktop installers.
- Apple notarization, Windows Authenticode and native hardware/device QA remain independent platform gates.
- Git tags, GitHub Releases, GHCR pushes, Chrome Web Store submissions and public binary distribution require explicit separate authorization.
- Last.fm API commercial use requires an appropriate agreement with Last.fm; MIT licensing of this repository does not grant rights to upstream services or data.

Detailed public-safe evidence is maintained in [the 1.0 QA report](1.0-qa-report.md) and [release checklist](release-checklist.md).
